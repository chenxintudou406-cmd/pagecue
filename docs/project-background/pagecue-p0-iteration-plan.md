## 1. 迭代目标

本轮不增加内容生产工作流，不建设负责人和任务执行体系。目标是把现有功能收口为五个可靠结果：

1. 所有业务数据以成员为主体，邀请码失效不破坏历史。
2. 管理员可准确投放给全体、成员组或指定成员；普通成员只能提醒自己。
3. 中重提醒不重叠，重提醒广播可送达目标成员。
4. 新网页打开后能够检查新内容，无需关闭或重启浏览器。
5. 后台能按提醒强度、互动分支和网站查看完整漏斗。

## 3. 核心数据原则

### 3.1 成员是唯一业务主体

所有新数据统一使用：

```text
createdByMemberId
submittedByMemberId
targetMemberIds
targetGroupIds
commentedByMemberId
interactedByMemberId
completedByMemberId
```

邀请码只存在于绑定流程：

```text
Invitation
  id
  codeHash
  memberId
  status
  createdAt
  usedAt
  revokedAt
```

业务记录不得使用邀请码或邀请码尾号作为主体。

### 3.2 历史记录不随凭证删除

- 删除或撤销邀请码，只影响该邀请码继续绑定；
- 撤销设备，只影响该设备继续访问；
- 停用成员，只影响未来读取权限；
- 历史提醒、评论、反馈、完成和日志继续关联原成员；
- 展示历史记录时保留成员当时的姓名快照，避免成员改名后无法理解旧记录。

### 3.3 提交信息备份

采用三层保存方式：

1. **业务实体**：保存当前可使用的提醒、成员、成员组和规则。
2. **不可变提交快照**：每次管理员、成员或 WorkBuddy 提交时，保存标准化字段、提交人、来源、请求编号、时间和内容哈希。
3. **追加式审计日志**：保存创建、修改、发布、到期、删除、评论、反馈和完成事件。

删除业务实体时，不删除提交快照和审计日志。

备份策略：

- 每次迁移和正式部署前自动备份；
- 每日生成加密数据备份；
- 保留最近7天每日备份、最近8周每周备份、最近12个月每月备份；
- 至少保留一份服务器外备份；
- 发布前执行一次真实恢复测试，而不只验证文件存在；
- 不备份网页正文、表单值、Cookie或完整查询参数。

## 4. Epic 与实施顺序

### Epic 0：冻结3.1.4基线

**目的**：保证本轮开发可回滚。

任务：

- 保存当前生产数据库副本；
- 保存两个3.1.4安装包；
- 将当前未提交代码形成明确 Git 提交；
- 建立本轮开发分支；
- 记录生产健康检查、数据数量和下载包哈希。

验收：

- 能从基线恢复服务；
- 两个3.1.4安装包可重新下载；
- Git 中不存在“线上已经使用但代码未提交”的文件。

### Epic 1：成员主体与数据安全

**目的**：邀请码、设备和成员身份解耦。

任务：

- 盘点提醒、评论、事件、绑定、邀请码和WorkBuddy提交中的身份字段；
- 将历史记录迁移为稳定 `memberId`；
- 补齐创建人和提交人姓名快照；
- 新增不可变提交快照；
- 删除邀请码时不级联删除业务数据；
- 停用成员后保留历史展示；
- 增加迁移前后数量校验；
- 实现每日和部署前备份。

验收：

- 邀请码删除后，原成员提醒、评论和日志数量不变；
- 设备撤销后，历史记录仍能查看；
- 成员改名后，当前姓名更新，历史提交仍能识别；
- 同一提交请求重复发送不会创建两条记录；
- 备份可以恢复到独立测试目录并通过数据数量校验。

### Epic 2：提醒投放范围

**目的**：管理员不会误发，成员不能给他人派发。

管理员创建组织提醒时三选一：

```text
全体成员
指定成员组
指定成员
```

普通成员创建个人提醒时：

```text
目标成员 = 当前登录成员
不可编辑
```

任务：

- 后台将投放方式改成单选；
- 选择成员组后才显示成员组列表；
- 选择指定成员后才显示成员多选列表；
- 服务端拒绝互相冲突的投放参数；
- 服务端忽略普通成员伪造的目标成员；
- 完成成员组新增、编辑、删除和成员移动；
- 记录发布时的目标范围；
- 成员组变化影响未来可见性，但历史互动仍绑定具体成员。

验收：

- 管理员三种方式均能准确投放；
- 不能同时保存成员组和指定成员；
- 普通成员修改请求体也无法发给别人；
- 非目标成员无法通过接口读取提醒；
- 删除邀请码不会改变提醒目标或历史。

### Epic 3：操作提醒到期留存

**目的**：到期后停止打扰，但信息不丢失。

任务：

- 知识提醒默认永久；
- 操作提醒继续保留开始时间和有效期；
- 到期操作提醒从插件启动数据中停止下发；
- 后台增加“已到期”筛选；
- 到期提醒正文、目标、提交人、评论、点赞/点踩、完成和事件继续保留；
- 管理员直接删除时，活动记录可以消失，但不可变提交快照和审计日志仍保留。

验收：

- 到期前可正常命中；
- 到期后不再匹配、不再弹窗；
- 后台可以查看到期提醒及全部历史互动；
- 修改有效期重新激活后可以再次命中；
- 数据迁移不会把知识提醒错误设置为到期。

### Epic 4：统一提醒坞与强提醒广播

**目的**：中重提醒明显但不遮挡工作页面。

#### 中重提醒坞

- 页面只存在一个主动提醒容器；
- 一次显示一张；
- 支持上一条、下一条和总数；
- 中提醒确认或完成后进入冷却；
- 重提醒按管理员规则持续显示；
- 用户状态按成员隔离；
- 多标签页只在当前活动标签页主动展示，其他标签页显示角标。

#### 强提醒广播

提醒新增：

```text
triggerMode:
  page_match
  broadcast
```

`broadcast` 不依赖页面关键词：

- 管理员可投放给全体、成员组或指定成员；
- 有 Web Push 时立即通知在线插件；
- 无 Web Push 时，目标成员下一次打开普通网页后显示；
- 同一提醒版本、同一成员只生成一条待展示记录；
- 多条广播进入提醒坞排队；
- 浏览器设置页等不可注入页面仅显示角标，进入普通网页后再展示。

验收：

- 同时命中5条中重提醒时不出现重叠卡片；
- 用户可逐条切换；
- 广播提醒不需要制造隐藏关键词；
- Chrome/Edge在Push可用时可以近实时收到；
- 搜狗/360打开新网页后可以收到；
- 不需要关闭或重启浏览器；
- 非目标成员不接收广播。

### Epic 5：打开页面轻量同步

**目的**：减少对 Web Push 的依赖，并控制服务器请求。

触发时机：

- 新标签页打开普通网页；
- 当前标签页跳转；
- 刷新；
- 切回已经打开的标签页；
- SPA路由变化；
- 浏览器启动；
- 每小时兜底。

同步逻辑：

```text
页面可扫描
→ 检查本地节流
→ 请求 /api/version
→ 版本未变化：结束
→ 版本变化：请求成员可见的增量或 bootstrap
→ 更新本地缓存
→ 重新扫描当前页面
```

约束：

- 多标签页共用浏览器级节流；
- 一分钟内最多一次版本检查；
- 版本接口支持 ETag/304；
- 页面匹配仍在本地；
- 请求中不包含页面正文或完整网址；
- 一直停留在同一页面时保留每小时兜底。

验收：

- 新规则发布后，目标用户打开新网页即可获得；
- 未变化时只产生轻量304请求；
- 连续打开10个网页，一分钟内最多进行一次版本检查；
- 断网时继续使用本地规则；
- 恢复网络后能够补传互动事件。

### Epic 6：多路径提醒漏斗

**目的**：不把所有用户行为强行解释成一条直线。

#### 总路径

```text
设置/发布
  ↓
命中提醒
  ↓
点击展开
  ↓
操作互动
  ├─ 点击链接
  ├─ 打开评论
  ├─ 提交评论
  ├─ 操作提醒完成
  ├─ 点赞
  └─ 点踩
```

“操作互动”先统计是否发生过任意互动，再分别统计各互动类型。

#### 轻提醒路径

轻提醒没有主动弹窗，单独计算：

```text
设置/发布
→ 页面命中
→ 高亮展示
→ 点击高亮/标记
→ 展开卡片
→ 各类互动
```

核心指标：

- 高亮点击率；
- 展开率；
- 任意互动率；
- 点赞/点踩率；
- 链接点击率；
- 评论率。

#### 中重提醒路径

中和重都有主动卡片，合并为一套主漏斗，但可按强度筛选：

```text
设置/发布
→ 页面命中
→ 弹窗展示
→ 展开完整内容
→ 任意互动
→ 各互动分支
```

核心指标：

- 弹窗到展开率；
- 任意互动率；
- 链接点击率；
- 评论率；
- 操作完成率；
- 点赞/点踩率。

#### 事件模型

```text
eventId
memberId
memoId
memoVersion
memoType
intensity
pageBucket
action
presentation
occurredAt
deviceId
```

建议事件：

```text
published
matched
highlight_shown
highlight_opened
popup_shown
expanded
link_opened
link_copied
comment_opened
comment_submitted
operation_completed
feedback_up
feedback_down
```

所有写入使用 `eventId` 幂等去重，避免离线补传造成重复统计。

#### 点赞/点踩

- 每张展开卡片显示小型“有用/无用”按钮；
- 轻提醒点击展开后显示；
- 中重提醒展开后显示；
- 同一成员对同一提醒版本保留一个当前反馈；
- 再次点击可以修改反馈；
- 管理后台统计点赞数、点踩数和反馈人数。

验收：

- 轻提醒和中重提醒拥有独立漏斗；
- 任意互动人数与各互动分支数量可同时查看；
- 同一离线事件重复补传不会重复计数；
- 评论打开和评论提交分开记录；
- 点赞改为点踩后不会同时计算为两份当前反馈；
- 不使用停留时长作为主要价值指标。

### Epic 7：网站维度漏斗

**目的**：判断知识在哪些真实工作网站中产生价值。

默认只保存和展示一级业务域名，不保存完整路径或查询参数。

示例：

```text
www.chemicalbook.com         → chemicalbook.com
supplier.chemicalbook.com    → chemicalbook.com
www.biochemsafebuy.com/*     → biochemsafebuy.com
www.biochemsafebuy.com/admin → biochemsafebuy.com/admin
```

Biochemsafebuy 特殊拆分规则：

- `/admin`、`/admin/`及其子路径归为 `biochemsafebuy.com/admin`；
- 其他路径归为 `biochemsafebuy.com`。

后台支持按以下维度筛选：

- 全部网站；
- 一级域名；
- Biochemsafebuy普通页面；
- Biochemsafebuy后台；
- 提醒类型；
- 轻/中/重；
- 成员组；
- 提醒。

展示：

- 设置/发布数；
- 命中成员数和命中次数；
- 展开成员数和展开率；
- 任意互动成员数和互动率；
- 链接、评论、完成、点赞、点踩分支；
- 轻提醒专属高亮点击率；
- 中重提醒专属弹窗展开率。

验收：

- ChemicalBook不同子域合并；
- Biochemsafebuy普通页面和后台分开；
- 统计中不出现完整业务URL和查询参数；
- 同一成员重复刷新既可看次数，也可看去重人数；
- 管理员可以从网站总览进入提醒明细，但不建设额外网站子页面。

验收：
